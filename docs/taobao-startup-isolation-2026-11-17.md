# 淘宝启动阶段隔离记录（2026-11-17）

## 当前结论

淘宝业务尚未恢复。alpha.9 的请求状态观察正常工作；本轮淘宝原生实验功能全部关闭。启动前移除 MagiCap 的两处证书覆盖后，新的购物车请求仍收到 HTTP 419。

本文记录可复核的边界，不把某个错误码等同于已定位的服务器规则。

## 启动前移除 MagiCap 覆盖

使用独立临时程序观察新启动的淘宝主进程。程序用 pidfd、包名、UID 和启动时间限定目标，确认其挂载命名空间独占，暂停所有目标线程后再检查已加载库和挂载结构。只有已知 SG 库尚未映射、路径结构符合预期且不存在共享传播时才继续。

先执行不修改挂载的启动对照，再执行移除覆盖的试验：

| 检查 | 不修改挂载的对照 | 移除 MagiCap 覆盖 |
| --- | --- | --- |
| 暂停至恢复 | 31 ms | 31 ms |
| 已知 SG 库映射 | 未发现 | 未发现 |
| 普通 umount 次数 | 0 | 2 |
| 目标进程恢复 | 已确认 | 已确认 |
| 非目标挂载快照 | 3 个均未变 | 3 个均未变 |
| 超时或部分变更 | 无 | 无 |

试验只移除了淘宝进程内 /apex/com.android.conscrypt/cacerts 和 /data/local/tmp/sys-ca-copy 顶层的 MagiCap bind。原生状态改写、probe、business trace 和环境兼容均保持关闭，实际加载日志确认 native_hooks=skipped。

移除后，新响应 mtop.trade.query.bag 在过滤器入口为 HTTP 419，后续读取为 ANDROID_SYS_API_41X_ANTI_ATTACK；请求记录时间均晚于目标进程恢复。另一次恢复普通继承挂载后的蜂窝网络启动也产生新的购物车 HTTP 419。没有用拒绝页消失或响应缺失作为成功标准。

这说明：在已知 SG 库映射前移除上述 MagiCap 覆盖，仍不足以恢复本次购物车业务。它不证明不存在更早的 Java 初始化、继承状态、历史服务端状态或其他环境影响。

## 仍存在的底层 CA 覆盖

独立克隆挂载命名空间检查确认，移除 MagiCap 后还保留 CA Installer 的 tmpfs 层。安装脚本会将额外证书复制到 tmpfs，再绑定到 Conscrypt 目录。

| 视图 | 证书数量 |
| --- | ---: |
| MagiCap 顶层 | 152 |
| CA Installer tmpfs 下层 | 151 |
| 原始只读 Conscrypt APEX | 149 |

克隆中移除下层后，原始 APEX 由 erofs 承载；临时别名下是空目录。完整证书集合已在私有证据中核对。克隆操作前后，真实淘宝进程的 mountinfo 完全一致。

恢复原始 149 张证书视图是另一项独立试验；本节不把它写成已经在真实淘宝进程完成的修复。

## 网络对照边界

此前按 UID 绕过 MagicNet 的试验已撤回。本轮未更改 MagicNet 全局路由策略。
